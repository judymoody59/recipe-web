# 로그인·회원가입 화면

로그인 화면과 3단계 회원가입 화면의 모양과 동작을 정한다. API 를 호출하지 않고 더미 데이터로
동작한다.

## 1. 범위

### 만드는 것

- 로그인 화면 — 아이디·비밀번호 입력, 입력 상태 표시, 오류 표시, 로그인 버튼, 회원가입 이동
- 회원가입 화면 — 단계 표시, 1→2→3단계 이동, 단계별 입력과 검증, 프로필 사진 선택,
  선호 카테고리 선택, 완료 화면
- 두 화면이 쓰는 더미 계정 데이터와 더미 올리기 함수, `Category` 타입

### 만들지 않는 것

- 홈·마이페이지 화면
- 완료 화면의 "마이페이지로 이동"·"홈으로 이동" 버튼의 이동 연결
- 로그인 상태 보관, 자동 로그인, 로그아웃
- 소셜 로그인, 아이디·비밀번호 찾기
- 기준 폭과 다른 창에 맞춘 비례 축소·반응형 배치

## 2. 시안

시안은 `docs/design/11/` 에 있다. 3840×2160 이미지이고 **기준 화면 폭 1920px 의 2배**다.
이 문서의 px 값은 전부 기준 폭 1920px 에서의 값이다(시안 픽셀 ÷ 2).

| 파일 | 화면·상태 |
|---|---|
| `login.png` | 로그인 — 입력 전 |
| `login-id-filled.png` | 로그인 — 아이디만 입력 |
| `login-filled.png` | 로그인 — 아이디·비밀번호 모두 입력 |
| `login-error.png` | 로그인 — 오류 |
| `signup-step1.png` | 회원가입 1단계 — 아이디/비밀번호 설정 |
| `signup-step2.png` | 회원가입 2단계 — 프로필 설정 |
| `signup-step3.png` | 회원가입 3단계 — 회원가입 완료 |

배치·비율·여백은 시안과 최대한 같게 맞춘다. 글자 크기 수치와 시안의 비율이 어긋나면 시안의
비율을 따른다.

## 3. 주소와 이동

| 주소 | 화면 |
|---|---|
| `/login` | 로그인 |
| `/signup` | 회원가입 (세 단계 모두) |

| 어디서 | 무엇을 하면 | 어디로 |
|---|---|---|
| 로그인 | 로그인 성공 | `/` |
| 로그인 | "회원가입 →" 누름 | `/signup` |
| 회원가입 1단계 | "취소" 누름 | `/login` |
| 회원가입 1단계 | "다음" 누름, 검증 통과 | 2단계 |
| 회원가입 2단계 | "이전" 누름 | 1단계 |
| 회원가입 2단계 | "다음" 누름, 검증 통과, 가입 성공 | 3단계 |
| 회원가입 2단계 | "다음" 누름, 아이디 중복 | 1단계 |
| 회원가입 3단계 | "마이페이지로 이동"·"홈으로 이동" 누름 | 이동하지 않는다 |

- 회원가입의 단계는 **화면 상태**다. 주소도 방문 기록도 단계마다 바뀌지 않는다
- 새로고침하면 1단계부터 시작하고 입력값은 비어 있다
- 브라우저 뒤로가기는 단계를 되돌리지 않고 `/signup` 에 들어오기 전 화면으로 간다

## 4. 공통 모양

### 4-1. 화면 틀

- 배경은 흰색이다
- 모든 크기는 **고정 px** 다. 창 폭이 1920px 와 달라도 크기를 바꾸지 않고 내용을 가로 가운데에
  둔다
- 내용이 차지하는 가장 넓은 폭은 1436px 이다(회원가입 화면의 단계 표시와 아래 버튼 줄,
  기준 폭에서 x 242–1678)
- 글꼴은 시스템 글꼴이다. 글꼴 파일이나 글꼴 패키지를 더하지 않는다

### 4-2. 상단 바

로그인·회원가입 화면 모두 맨 위에 둔다.

| 항목 | 값 |
|---|---|
| 바 | 창 전체 폭, 높이 150px, 흰색. 아래쪽으로 약 40px 에 걸쳐 옅어지는 그림자(바 바로 아래 `#F1F1F1` 에서 흰색으로) |
| 로고 자리 | 180×58px, 바의 가로 가운데, 바 위에서 46px. 색 `#F4F4F4`, 모서리 약 6px |
| 로고 글자 | "로고". 색 `#ABABAB`, 약 18px, 굵게. 로고 자리 한가운데 |

로고 자리는 누르는 요소가 아니다.

### 4-3. 색

| 색 | 쓰는 곳 |
|---|---|
| `#ABABAB` | 빈 입력칸의 placeholder·아이콘, 로고 글자, 프로필 사진 원, 선호 카테고리의 ▼ |
| `#B0B0B0` | 채운 버튼(비활성 로그인 버튼, "다음"), 현재 단계 알약의 채움, 나머지 알약의 테두리·글자, 단계 사이 점선과 꺾쇠, "취소"·"이전" 의 테두리·글자 |
| `#292D32` | 값이 들어간 입력칸의 글자·아이콘·가림 점, 활성 로그인 버튼 |
| `#FFFFFF` | 배경, 입력칸 안쪽, 채운 버튼과 현재 단계 알약의 글자, "취소"·"이전" 의 안쪽 |
| `#FF0000` | 오류 문구 |
| `#949698` | "회원가입 →" 의 글자와 화살표 |
| `#87898C` (근사) | 입력칸 테두리. 시안에서 `#85878A`–`#898B8D` 로 읽힌다 |
| `#5D5D5D` | 프로필 사진 원 안의 올리기 아이콘, "프로필 사진" 글자 |
| `#000000` | 화면 제목 "로그인", 완료 문구, 완료 화면 버튼의 글자 |
| `#EEEEEE` / `#797979` | 완료 화면 버튼의 채움 / 테두리 |
| `#F4F4F4` | 로고 자리 |

### 4-4. 글자

| 글자 | 크기 | 굵기 |
|---|---|---|
| 화면을 넘기는 버튼 — "로그인", "다음", "이전", "취소" | 36px | semi bold |
| 입력칸의 placeholder 와 입력한 값, "프로필 사진" | 28px | medium |
| 화면 제목 "로그인" | 36px | 굵게 |
| 완료 화면 버튼 — "마이페이지로 이동", "홈으로 이동" | 36px | 보통 |
| 완료 문구 | 약 40px, 줄 간격 60px | 굵게 |
| 단계 알약의 글자 | 약 24px | 굵게 |
| 오류 문구 | 약 24px, 줄 간격 32px | 보통 |
| "회원가입 →" | 약 24px | 보통 |
| 로고 글자 | 약 18px | 굵게 |

"약" 이 붙은 크기는 시안의 글자 높이를 같은 시안 안의 36px·28px 글자와 견주어 환산한 값이다.

### 4-5. 입력칸

| 항목 | 값 |
|---|---|
| 크기 | 600×120px |
| 테두리 | 2px, `#87898C` (근사). 모서리 약 6px. 테두리 안쪽으로 옅은 그림자 |
| 아이콘 | 칸 왼쪽에서 아이콘 중심까지 약 66px, 세로 가운데. 크기 약 37–46px |
| 글자 | 칸 왼쪽에서 132px 떨어진 곳에서 시작, 세로 가운데 |
| 입력칸 사이 | 세로 30px |

- **빈 칸** — placeholder 와 아이콘이 `#ABABAB`
- **값이 들어간 칸** — 글자와 아이콘이 `#292D32`. 테두리는 바뀌지 않는다
- **비밀번호·비밀번호 확인** — 값을 가려서 보여준다. 시안의 가림 점은 지름 약 21px, `#292D32`

### 4-6. 아이콘

아이콘 패키지를 더하지 않는다. 아래 7종을 리포 안의 SVG 로 둔다.

| 아이콘 | 쓰는 곳 |
|---|---|
| 사람 | 아이디 입력칸 |
| 방패 | 비밀번호·비밀번호 확인 입력칸 |
| 명찰 | 닉네임 입력칸 |
| 편지 | 이메일 입력칸 |
| 얼굴 | 선호 카테고리 |
| 올리기 | 프로필 사진 원 |
| 화살표 | "회원가입 →" |

아이콘 색은 놓인 자리의 상태를 따른다(4-5).

### 4-7. 오류 문구

로그인과 회원가입이 같은 형식을 쓴다.

- 입력칸 묶음과 그 아래 버튼 사이에 둔다
- 색 `#FF0000`, 가로 가운데 정렬
- **한 번에 한 문구만** 보여준다
- 문구는 버튼을 누른 결과로만 바뀐다. 입력값을 고치는 동안에는 그대로 있고, 다음에 버튼을 눌러
  통과하면 사라지고 다시 걸리면 그때의 문구로 바뀐다

## 5. 로그인 화면

### 5-1. 구성

위에서 아래로, 전부 가로 가운데다. 세로 위치의 기준은 `login.png` 다.

| 요소 | 내용 | 위치·크기 (기준 폭 1920px) |
|---|---|---|
| 제목 | "로그인" | 글자 윗선 y 285 |
| 아이디 입력칸 | 사람 아이콘, placeholder "아이디" | x 660, y 392, 600×120 |
| 비밀번호 입력칸 | 방패 아이콘, placeholder "비밀번호" | x 660, y 542, 600×120 |
| 로그인 버튼 | "로그인" | x 660, y 747, 600×120, 양 끝이 반원 |
| 회원가입 링크 | "회원가입 →" (화살표는 아이콘) | 버튼 아래 31px |

`login-id-filled.png`·`login-filled.png` 에서는 색만 따른다. 입력에 따라 제목·입력칸·버튼의
위치가 바뀌지 않는다.

### 5-2. 로그인 버튼

| 상태 | 조건 | 모양 | 동작 |
|---|---|---|---|
| 비활성 | 아이디 또는 비밀번호가 비어 있다 | 채움 `#B0B0B0`, 글자 흰색 | 눌리지 않는다 |
| 활성 | 아이디와 비밀번호가 모두 한 글자 이상 | 채움 `#292D32`, 글자 흰색 | 누르면 로그인을 시도한다 |

활성 색은 시안에 없다. `login-filled.png`·`login-error.png` 의 버튼 색은 따르지 않는다.

### 5-3. 로그인 판정

입력한 아이디·비밀번호를 더미 계정(7장)과 견준다. 입력값은 다듬지 않고 그대로 견준다.

- **성공** — `loginId` 가 같은 계정이 있고 비밀번호가 같다. `/` 로 이동한다.
  로그인 응답(`accessToken`, `user`)은 어디에도 보관하지 않는다
- **실패** — 그 밖의 모든 경우. 아이디가 없는 것과 비밀번호가 틀린 것을 구분하지 않고 같은
  오류 하나를 보여준다. 입력값은 그대로 둔다

### 5-4. 오류 상태

기준은 `login-error.png` 다.

- 문구 — 두 줄, 줄을 아래처럼 나눈다

  ```
  아이디 또는 비밀번호를 잘못 입력했습니다.
  입력하신 내용을 다시 확인해주세요.
  ```

- 위치 — 비밀번호 입력칸과 로그인 버튼 사이. 입력칸 아래 41px 에서 첫 줄 글자가 시작하고,
  둘째 줄 글자 아래 28px 에 로그인 버튼이 온다
- 오류가 보이는 동안 로그인 버튼과 회원가입 링크는 그만큼(38px) 아래로 내려간다.
  제목과 입력칸은 움직이지 않는다

## 6. 회원가입 화면

### 6-1. 단계 표시

세 단계 모두 상단 바 아래 같은 자리에 둔다.

| 항목 | 값 |
|---|---|
| 알약 | 273×70px, 양 끝이 반원. y 230. x 242 / 824 / 1405 |
| 글자 | 순서대로 "아이디/비밀번호 설정", "프로필 설정", "회원가입 완료" |
| 현재 단계 | 채움 `#B0B0B0`, 글자 흰색 |
| 나머지 단계 | 채움 없음, 테두리 2px `#B0B0B0`, 글자 `#B0B0B0` |
| 알약 사이 | `#B0B0B0` 점선. 가운데에 오른쪽을 가리키는 꺾쇠 |

- **현재 단계 하나만** 채운다. 지나온 단계도 채우지 않는다
- 알약은 누르는 요소가 아니다

### 6-2. 아래 버튼 줄 (1·2단계)

| 버튼 | 위치·크기 | 모양 |
|---|---|---|
| 왼쪽 — 1단계 "취소", 2단계 "이전" | x 242, y 881, 200×84, 양 끝이 반원 | 채움 없음, 테두리 1px `#B0B0B0`, 글자 `#B0B0B0` |
| 오른쪽 — "다음" | x 1478, y 881, 200×84, 양 끝이 반원 | 채움 `#B0B0B0`, 글자 흰색 |

"다음" 은 입력 여부와 관계없이 언제나 눌린다. 검증은 눌렀을 때 한다(6-6).

### 6-3. 1단계 — 아이디/비밀번호 설정

기준은 `signup-step1.png` 다.

| 입력칸 | 아이콘 | placeholder | 위치 |
|---|---|---|---|
| 아이디 | 사람 | "아이디" | x 660, y 395 |
| 비밀번호 | 방패 | "비밀번호" | x 660, y 545 |
| 비밀번호 확인 | 방패 | "비밀번호 확인" | x 660, y 695 |

### 6-4. 2단계 — 프로필 설정

기준은 `signup-step2.png` 다.

| 요소 | 내용 | 위치·크기 |
|---|---|---|
| 프로필 사진 원 | 지름 221px, 채움 `#ABABAB`. 가운데에 올리기 아이콘(약 67px, `#5D5D5D`) | x 491, y 477 |
| 글자 | "프로필 사진", `#5D5D5D` | 원 아래, 원과 가로 가운데를 맞춘다. 글자 윗선 y 727 |
| 닉네임 입력칸 | 명찰 아이콘, placeholder "닉네임" | x 809, y 395 |
| 이메일 입력칸 | 편지 아이콘, placeholder "이메일" | x 809, y 545 |
| 선호 카테고리 | 얼굴 아이콘, placeholder "선호 카테고리", 오른쪽에 ▼ | x 809, y 695 |

**프로필 사진**

- 원을 누르면 파일을 고르는 창이 열린다. 그 창에서는 **이미지 파일만** 고를 수 있다.
  파일 크기에는 제한이 없다
- 파일을 고르면 더미 올리기 함수(7-3)가 그 파일의 **브라우저 안의 주소**를 만들어 돌려준다.
  그 주소 하나를 원 안의 미리보기와 가입 요청의 `profileImageUrl` 에 같이 쓴다
- 사진을 고르면 그 사진이 **원 전체를 채운다.** 사진의 비율을 유지하고 원 밖으로 넘치는 부분은
  잘라낸다. 올리기 아이콘은 보이지 않는다
- 사진을 고른 뒤 원을 다시 누르면 파일을 고르는 창이 다시 열리고, 새로 고른 사진으로 바뀐다
- 고르지 않으면 `profileImageUrl` 은 `null` 이다
- 프로필 사진에 관한 오류 문구는 없다

**선호 카테고리**

- 입력칸과 크기·테두리가 같은 드롭다운이다. ▼ 는 `#ABABAB`, 칸 오른쪽에서 41px 안쪽.
  닫힌 모양은 시안을 따르고, 펼친 목록은 **브라우저 기본 선택 목록**을 쓴다
- 고를 수 있는 값은 `docs/api/recipe.md` 의 `Category` 5종이다

  | 화면 글자 | 값 |
  |---|---|
  | 한식 | `KOREAN` |
  | 중식 | `CHINESE` |
  | 일식 | `JAPANESE` |
  | 양식 | `WESTERN` |
  | 기타 | `OTHERS` |

- 고르면 placeholder 자리에 고른 값의 화면 글자가 들어가고, 글자와 얼굴 아이콘이 `#292D32` 가 된다
- 고르지 않으면 `preferredCategory` 는 `null` 이다

### 6-5. 3단계 — 회원가입 완료

기준은 `signup-step3.png` 다.

| 요소 | 내용 | 위치·크기 |
|---|---|---|
| 완료 문구 | 두 줄, 가로 가운데 | 첫 줄 글자 윗선 y 517 |
| 왼쪽 버튼 | "마이페이지로 이동" | x 535, y 777, 400×90, 양 끝이 반원 |
| 오른쪽 버튼 | "홈으로 이동" | x 985, y 777, 400×90, 양 끝이 반원 |

완료 문구는 아래처럼 줄을 나눈다.

```
회원가입이 성공적으로
완료되었습니다!
```

두 버튼은 채움 `#EEEEEE`, 테두리 1px `#797979`, 글자 `#000000` 이다. 눌러도 아무 일도 일어나지
않는다. 3단계에는 아래 버튼 줄("이전"·"다음")이 없다.

### 6-6. 검증

"다음" 을 누를 때 그 단계의 규칙을 **위에서부터** 검사하고, 처음 걸린 규칙의 문구 하나만
보여준다(4-7). 걸리면 단계를 넘기지 않는다. 입력값은 다듬지 않고 그대로 검사한다.

| 단계 | 순서 | 규칙 | 걸렸을 때 문구 |
|---|---|---|---|
| 1 | 1 | 아이디 4자 이상 | 아이디는 4자 이상 입력해주세요. |
| 1 | 2 | 비밀번호 8자 이상 | 비밀번호는 8자 이상 입력해주세요. |
| 1 | 3 | 비밀번호 확인이 비밀번호와 같다 | 비밀번호가 일치하지 않습니다. |
| 2 | 1 | 닉네임이 한 글자 이상 | 닉네임을 입력해주세요. |
| 2 | 2 | 이메일이 이메일 형식이다 | 이메일 형식이 올바르지 않습니다. |

- 최대 길이와 허용 문자에는 제한이 없다
- 이메일 형식 — `@` 가 하나이고, 그 앞과 뒤가 비어 있지 않고, 뒤쪽에 `.` 이 있으며, 공백이 없다
- 프로필 사진과 선호 카테고리는 선택이다. 검사하지 않는다
- 문구는 한 줄이고, 입력칸 묶음(아래 끝 y 815)과 아래 버튼 줄(위 끝 y 881) 사이에 둔다.
  버튼 줄의 위치는 바뀌지 않는다

### 6-7. 가입 요청과 아이디 중복

2단계의 검증을 통과하면 가입을 요청한다(7-2).

- **성공** — 3단계로 간다. 가입만으로 로그인되지 않는다
- **아이디 중복** — 1단계로 돌려보내고 거기서 "이미 사용 중인 아이디입니다." 를 보여준다.
  1·2단계의 입력값은 그대로 있다

아이디 중복은 가입 요청에서만 판정한다. 1단계 "다음" 에서는 판정하지 않는다.

### 6-8. 입력값 유지

- 1단계와 2단계를 오가도 입력값(프로필 사진과 선호 카테고리 포함)은 그대로 있다
- 다른 단계의 오류 문구는 따라오지 않는다. 각 단계는 자기 문구만 보여준다
- 새로고침하거나 `/signup` 을 떠났다 돌아오면 비어 있다

## 7. 더미 데이터

API 를 호출하지 않는다. 더미 데이터의 필드 이름·타입·응답 형태는 `docs/api/` 와 같다.

### 7-1. 계정 저장

- 계정은 **브라우저 메모리에만** 둔다. 시드 계정과 그 세션에서 가입한 계정이 들어 있다
- 새로고침하면 가입한 계정은 사라지고 시드 계정만 남는다
- 계정 하나는 `docs/api/auth.md` 의 `User` 에 비밀번호를 더한 것이다. 비밀번호는 판정에만 쓰고
  어떤 응답에도 담지 않는다

시드 계정은 하나다. `docs/api/auth.md` 의 예시와 같은 값이다.

| 필드 | 값 |
|---|---|
| `userId` | `1` |
| `loginId` | `recipe01` |
| 비밀번호 | `pass1234` |
| `nickname` | `요리왕` |
| `email` | `recipe01@example.com` |
| `profileImageUrl` | `null` |
| `preferredCategory` | `KOREAN` |
| `role` | `USER` |
| `createdAt` · `updatedAt` | `2024-02-09T09:46:44Z` |

### 7-2. 더미 함수

`docs/api/auth.md` 의 요청·응답 형태를 그대로 따른다. 실패는 `docs/api/README.md` 의 오류 틀
`{ code, message }` 로 알린다. 화면은 `code` 로 분기하고, 화면에 보이는 문구는 이 문서가 정한다.

| 함수 | 요청 | 성공 | 실패 |
|---|---|---|---|
| 로그인 | `{ loginId, password }` | `{ accessToken, user }`. `accessToken` 은 비어 있지 않은 더미 문자열 | `INVALID_CREDENTIALS` — 아이디가 없거나 비밀번호가 틀렸다 |
| 회원가입 | `{ loginId, password, nickname, email, profileImageUrl, preferredCategory }` | 만들어진 `User` | `DUPLICATED_LOGIN_ID` — 같은 `loginId` 의 계정이 이미 있다 |

회원가입이 만드는 `User`:

- `userId` — 들어 있는 계정의 가장 큰 `userId` + 1
- `role` — `USER`
- `createdAt` · `updatedAt` — 가입 시각, UTC 기준 ISO 8601 문자열. 둘이 같다
- `profileImageUrl` · `preferredCategory` — 값이 없으면 필드를 빼지 않고 `null`
- "비밀번호 확인" 은 요청에 담지 않는다

### 7-3. 더미 올리기 함수

`docs/api/upload.md` 의 응답 형태를 따른다.

| 함수 | 요청 | 성공 |
|---|---|---|
| 이미지 올리기 | 파일 한 개 | `{ url }` — 그 파일을 가리키는 브라우저 안의 주소 |

## 8. 코드 위치

| 자리 | 두는 것 |
|---|---|
| `src/app/login/`, `src/app/signup/` | 라우트. 페이지만 두고 로직은 도메인 모듈에 둔다 |
| `src/domain/auth/` | 로그인·회원가입 화면의 컴포넌트, 검증, 더미 계정과 로그인·회원가입 함수, `User`·`Role` 타입 |
| `src/domain/upload/` | 더미 올리기 함수 |
| `src/domain/recipe/types/` | `Category` 타입 |
| `src/components/` | 도메인에 묶이지 않는 공용 UI — 입력칸, 버튼, 상단 바, 아이콘 |

- `src/domain/auth` 가 `src/domain/upload` 의 올리기 함수를 import 한다
- `src/domain/auth` 가 `src/domain/recipe` 의 `Category` 타입을 import 한다
- 새 의존 패키지를 더하지 않는다

## 9. 수용 기준

### 로그인

- [ ] `/login` 이 `login.png` 와 같은 배치로 보인다 — 상단 바, 제목, 입력칸 2개, 로그인 버튼, 회원가입 링크
- [ ] 값을 넣은 입력칸은 글자와 아이콘이 `#292D32` 가 되고, 비우면 `#ABABAB` 로 돌아온다
- [ ] 비밀번호는 가려서 보인다
- [ ] 아이디나 비밀번호가 비어 있으면 로그인 버튼이 `#B0B0B0` 이고 눌리지 않는다
- [ ] 둘 다 입력하면 로그인 버튼이 `#292D32` 가 되고 눌린다
- [ ] 시드 계정(`recipe01` / `pass1234`)으로 로그인하면 `/` 로 이동한다
- [ ] 없는 아이디로 로그인해도, 있는 아이디에 틀린 비밀번호로 로그인해도 같은 두 줄 오류 문구가 빨간색으로 비밀번호 입력칸과 로그인 버튼 사이에 보인다
- [ ] 로그인에 성공한 뒤 브라우저 저장소에 `accessToken`·`user` 가 남지 않는다
- [ ] "회원가입 →" 을 누르면 `/signup` 으로 이동한다

### 회원가입

- [ ] `/signup` 에 들어가면 1단계가 `signup-step1.png` 와 같은 배치로 보이고 첫 알약만 채워져 있다
- [ ] 단계가 바뀌면 그 단계의 알약만 채워진다. 알약은 눌러도 반응하지 않는다
- [ ] 1단계 "취소" 를 누르면 `/login` 으로 이동한다
- [ ] 1단계에서 6-6 의 규칙에 걸리면 처음 걸린 규칙의 문구 하나만 보이고 2단계로 넘어가지 않는다
- [ ] 2단계가 `signup-step2.png` 와 같은 배치로 보인다
- [ ] 프로필 사진 원을 누르면 열리는 파일 선택 창은 이미지 파일만 고르게 한다
- [ ] 사진을 고르면 그 사진이 원 전체를 채우고 올리기 아이콘이 보이지 않는다
- [ ] 사진을 고른 뒤 원을 다시 눌러 다른 사진을 고르면 그 사진으로 바뀐다
- [ ] 선호 카테고리에서 한식·중식·일식·양식·기타 중 하나를 고를 수 있다
- [ ] 2단계에서 "이전" 을 눌러 1단계로 갔다가 다시 오면 양쪽 입력값이 그대로 있다
- [ ] 2단계에서 6-6 의 규칙에 걸리면 처음 걸린 규칙의 문구 하나만 보이고 3단계로 넘어가지 않는다
- [ ] 프로필 사진과 선호 카테고리를 고르지 않아도 가입된다
- [ ] 이미 있는 아이디(`recipe01`)로 2단계 "다음" 을 누르면 1단계로 돌아가 "이미 사용 중인 아이디입니다." 가 보이고 입력값이 그대로 있다
- [ ] 가입에 성공하면 3단계가 `signup-step3.png` 와 같은 배치로 보인다
- [ ] 3단계의 두 버튼은 눌러도 이동하지 않는다
- [ ] 가입한 아이디·비밀번호로 `/login` 에서 로그인하면 성공한다
- [ ] 새로고침한 뒤에는 가입했던 계정으로 로그인되지 않는다
- [ ] `/signup` 에서 새로고침하면 1단계이고 입력값이 비어 있다
