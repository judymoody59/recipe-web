### 무엇을 어느 수준으로 검증하나

- 단위 테스트 — Vitest + jsdom + Testing Library. 대상 파일 옆에 `<이름>.test.ts(x)` 로 둔다
  (`src/**/*.test.{ts,tsx}` 만 수집한다). 분기가 있는 유틸·도메인 로직·zod 스키마·훅의 분기를 덮는다
- 컴포넌트 테스트 — Testing Library 로 렌더해 사용자가 보는 텍스트·역할로 찾는다. 구현 세부(내부
  상태·클래스 이름)를 단언하지 않는다
- E2E — Playwright, `tests/e2e/`. 화면을 가로지르는 흐름만. 아직 테스트가 없다
- 테스트 이름은 무엇을 검증하는지 한국어 문장으로 쓴다

### 외부 의존을 어떻게 다루나

- 외부 호스트에 붙지 않는다. 외부 백엔드도 없다
- 환경 변수는 `vitest.config.mts` 의 `test.env` 가 준다. 실제 `.env.local` 에 기대지 않는다
- 데이터 접근 함수를 테스트에서 무엇으로 대신할지는 아직 정하지 않았다. 데이터 소스가 정해지면 정한다

### 하지 않는 것

- 실제 현재 시각에 의존하지 않는다. 시각이 필요하면 `vi.useFakeTimers()` · `vi.setSystemTime()` 으로 고정한다
- 실제 시간 대기(`setTimeout` 으로 기다리기)를 쓰지 않는다. Testing Library 의 `findBy*` · `waitFor` 를 쓴다
- 스냅샷 테스트로 마크업 전체를 고정하지 않는다
